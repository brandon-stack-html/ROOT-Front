### BUG-01 — SKU POA-001 duplicado en store-mesas.js

- **Módulo:** Mesero / datos compartidos  
- **Archivo:** `assets/js/store-mesas.js` líneas 109 y 120  
- **Severidad:** Alta  

**Descripción:**  
Dos productos distintos comparten el mismo SKU `POA-001`:
- Mesa 8: `{ sku: 'POA-001', nombre: 'Postre del día', precio: 9000 }`
- Mesa 9: `{ sku: 'POA-001', nombre: 'Café Tinto', precio: 3500 }`

Si algún componente filtra o agrupa por SKU (inventario, facturación, KDS), los ítems de estas dos mesas colisionarán.

**Pasos para reproducir:**
1. Abrir `mesero/comandas.html` o `kds/main.html`
2. Ver las comandas de mesa 8 y mesa 9
3. Observar que "Postre del día" y "Café Tinto" podrían agruparse o confundirse si hay lógica de deduplicación por SKU

**Esperado:** Cada producto tiene un SKU único  
**Fix sugerido:** Cambiar `Café Tinto` a `CAF-001` en línea 120 de `store-mesas.js`

### BUG-02 — Nombre "Camila" inconsistente en 3 fuentes

- **Módulo:** Mesero  
- **Archivos:** `auth.js:89`, `mesero/perfil.html:355`, `assets/js/empleados.js:26`, `assets/js/data/nomina-mock.js:17`  
- **Severidad:** Alta (visible en demo ante stakeholders)  

**Descripción:**  
La mesera principal del rol demo tiene 3 nombres diferentes según el archivo:

| Fuente | Nombre | Iniciales |
|--------|--------|-----------|
| `auth.js` (rol switcher → topbar) | `Camila V.` | `CV` |
| `mesero/perfil.html` (fallback hardcoded) | `Camila Velásquez` | `CV` |
| `empleados.js` + `nomina-mock.js` (backoffice → nómina) | `Camila Rojas` | `CR` |

**Pasos para reproducir:**
1. Hacer login como **mesero** → avatar en topbar dice "Camila V." (CV, acento morado)
2. Ir a `mesero/perfil.html` → nombre "Camila Velásquez"
3. Ir a `backoffice/usuarios.html` → en lista aparece "Camila Rojas"
4. Ir a `backoffice/nomina.html` → "Camila Rojas"

**Esperado:** El mismo nombre en todos los módulos  
**Fix sugerido:** Unificar como `Camila Velásquez` / iniciales `CV` en `empleados.js` y `nomina-mock.js` (o viceversa). Cambiar la clave `name` en `auth.js:89` a nombre completo.

### BUG-04 — Cajero/Gerente pueden forzar URL a páginas restringidas

- **Módulo:** Auth  
- **Archivo:** `assets/js/auth.js:205-226`  
- **Severidad:** Media (demo — no es producción, pero se puede notar en una revisión)  

**Descripción:**  
`Auth.applySidebar()` para los roles `cajero` y `gerente` solo **oculta los nav-items** del sidebar. No hace redirect. Esto significa que si un cajero escribe directamente `backoffice/usuarios.html` en la barra de direcciones, la página carga con todo el contenido visible (solo sin el ítem en el sidebar).

El redirect automático solo funciona para `mesero` y `cocina` (que usan `__redirect__`).

**Pasos para reproducir:**
1. Hacer login como **cajero**
2. Escribir en la barra: `http://localhost:8000/backoffice/usuarios.html`
3. La página carga con datos de empleados visible

**Esperado:** Redirect a la home del cajero  
**Fix sugerido:** En `applySidebar()`, para roles `cajero` y `gerente`, agregar check de pathname igual al del `__redirect__` para páginas de su lista restringida.

### BUG-05 — nomina-imprimible.html ignora dark mode

- **Módulo:** Backoffice  
- **Archivo:** `backoffice/nomina-imprimible.html:12-72`  
- **Severidad:** Media  

**Descripción:**  
La página de nómina imprimible tiene **todos los colores hardcodeados** en modo claro (`background: #f4f4f5`, `color: #18181b`, `background: #4F46E5`, etc.). Si el usuario tiene dark mode activo y abre esta pantalla, el resultado puede ser inconsistente visualmente para una presentación.

**Nota:** Esta es una página de impresión, por lo que en un contexto real sería aceptable. Sin embargo, al navegar en la demo se verá en claro aunque el sistema esté en dark.

**Fix sugerido:** Agregar `@media print { ... }` con los colores hardcodeados (como están ahora), y fuera del print block usar variables CSS. O documentar que es intencional para impresión.

### BUG-06 — Avatar "El Buen Sabor" tiene background hex inline

- **Módulo:** Backoffice  
- **Archivo:** `backoffice/configuracion.html:233`  
- **Severidad:** Cosmética  

**Descripción:**  
El avatar de la empresa en el preview de factura tiene `style="background:#FED7AA"` (naranja hardcodeado). En dark mode el contraste de `color:#9A3412` sobre `#FED7AA` puede verse diferente de lo esperado, y no respeta el sistema de variables CSS.

```html
<div style="background:#FED7AA;color:#9A3412;...">BS</div>
```

**Fix sugerido:** Reemplazar con variables: `background:var(--state-warning-bg);color:var(--state-warning)` o similares.

### BUG-07 — Cambio de tema no se sincroniza entre tabs del navegador

- **Módulo:** Global  
- **Archivo:** `assets/js/theme.js`  
- **Severidad:** Cosmética  

**Descripción:**  
`theme.js` guarda el tema en `localStorage` pero no escucha el evento `storage`. Si se tienen dos tabs abiertos y se cambia el tema en una, la otra no actualiza hasta refresh.

**Fix sugerido:** Agregar en `bind()`:
```js
window.addEventListener('storage', function(e) {
  if (e.key === 'theme' && e.newValue) {
    document.documentElement.setAttribute('data-theme', e.newValue);
  }
});
```

### BUG-08 — Auth.current() auto-inicializa con admin si no hay sesión

- **Módulo:** Auth  
- **Archivo:** `assets/js/auth.js:145-154`  
- **Severidad:** Baja (comportamiento demo intencional, pero puede sorprender)  

**Descripción:**  
Si alguien abre directamente `backoffice/inventario.html` sin haber hecho login (localStorage vacío), `Auth.current()` crea automáticamente una sesión como admin. Esto significa que **cualquier URL del backoffice es accesible sin autenticación**, simplemente abriendo el archivo.

En demo es conveniente, pero si se presenta ante stakeholders que entiendan de seguridad puede generar preguntas.

**Fix sugerido:** Agregar en el init de páginas sensibles un check: `if no session → redirect to login`. O documentar que es comportamiento intencional de demo.
